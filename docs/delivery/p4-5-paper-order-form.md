# P4.5 — the application form in the paper order, one save

28 October 2026. On the user's approval of [the parity review](../planning/desktop-web-parity-review.md) ("يفضل حفظ واحد، نعم أوافق على المقترح. ابدأ"). Status: implemented locally with automated evidence on SQLite and a rendered browser check on an invented fixture; the grids remain separate forms until P4.6; MySQL re-run and staff acceptance remain open, as for the rest of Phase 4.

## What changed

- **`PaperOrder`** (`app/Services/Applications/PaperOrder.php`): the paper form's sequence for every form kind (project, link row, person, family membership, work, education, course, the six support grids, budget, power, risk, agriculture and rehabilitation rows), reconstructed from `Application_New_Form.Designer.cs`; which fields the desktop hides on the preliminary form (`Application_New_Form.cs:564–596`); internal columns the desktop computes (`Partnership`, `IsProjectOwner`, `P_NumAtHome`, `P_NumOfMembers`); yes/no columns, the birth year, the military values, ampere/watt and the cascading lists (subcategory → career, type → subtype, question → answer). `ApplicationService::fields()/relations()` and `PeopleService::fields()/relations()` return metadata in that order.
- **`LookupOptions`** (`app/Services/Operational/LookupOptions.php`): lists sorted as the desktop binds them (`Bind_Data`, `:832–845`: subcategory, career, priest, street and work by name; everything else by original id), labelled by the name column of the current locale, with the parent id for cascading lists.
- **One field renderer** (`resources/views/forms/fields.blade.php`), used by every form: fields and lists interleaved in the paper order with optional group headings; yes/no radio pairs for the flag columns; a four-digit **birth year** stored as 1 January (desktop `P_DOB_textBox`, `ParseExact "yyyy"`), `type="date"` for other dates unless the stored value is a historical sentinel such as `0000-00-00` (kept as text); the sex and military lists; ampere/watt; cascading lists filtered by their parent; required marks; "not recorded" boxes only on edit forms. A cleared date, number or choice is stored as null (desktop empty box). `blank_is_null` on the create form makes every blank box "not recorded".
- **Create form** (`applications/create.blade.php`): project form → applicant personal information → family book, as the desktop; full-only fields hidden; the first project type pre-selected; project number assigned on save (read-only hint).
- **Application page** (`applications/show.blade.php`): the paper form top to bottom — project form (number, full name, mobile read-only) · beneficiary story · applicant personal information · work and education flags · project information with the power, risk and budget grids · family (family book number read-only, living-with-family, losses, illness, assets) · aid from other sources, debts, help and home power · additional information · annexes · applicants and partners — with a sticky action bar (save, draft, print, drafts, submit full application). **One Save** (`ApplicationService::saveForm`) writes the project row, the beneficiary's link row and the beneficiary's person row in one transaction under the application's version (which already covers the person snapshot); a failure anywhere writes nothing. Grid rows keep their own forms, placed in their paper position (`form` attribute keeps the paper form's controls together), until P4.6.
- **Labels** in `lang/ar` follow the paper form wording (الكنية (AR)، القيد/الأمانة، المواليد، الطائفة، الهيئة الوسيطة، المنطقة (القرية)، ملكية المنزل، وصف المشروع، طبيعة المشروع، اسم المهنة، أسئلة الموافقات…); the missing `applications.complete/complete_hint/edit_household/support_hint/answer_hint` keys were added (D1).
- **Checklist** sections in the desktop order (key people · visits · experience with professional test / professional training / management training · team opinion · committee opinion · notes · rejection message), the meeting date above its members, examiner/observer labels; **loan** and **executive file** forms in the desktop field order with the 5-month default.
- Drafts of an existing application carry the link and person sections.

## Verification

`tests/Feature/PaperOrderTest.php` (5 tests): metadata order and internal columns; desktop list order and locale labels; the create form's section order, typed controls and absence of raw keys; birth year and blank boxes stored as the desktop; one save writing project, link and person rows together and rolling back on a person error. Full suite after the single-save page: 327 tests pass (9,172 assertions), one host-dependent skip. Rendered check in the desktop app's browser over the invented SQLite fixture (`MicroProjects-TestRuntime/p64-*`): a preliminary application saved from the reordered create form (streets by name, parishes by original id, birth year 1990 → 1990-01-01, blank boxes → null); the application page saved project name, story and the applicant's mother name in one click; 375px width without horizontal overflow; no console errors from the application.
