# Whole-table sharing proposal review

Reviewed 18 October 2026 by the coordinator, separate from the physical addendum author. This is metadata/design review, not user schema confirmation or runtime acceptance.

The archive audit was rerun against all five original ZIP/SQL hashes and all 616 parsed source-table counts. Result: 1,721,699 tuples, 61 nonempty equality groups across 58 names, plus 20 identical-empty groups. SQL numeric spelling and literal kinds remain distinct; text escapes and binary bytes are decoded without normalizing values. Hex and quoted literal tags are kept separate because identical decoded bytes can have different numeric-column semantics. This conservative method can reject semantically equivalent spellings, but must not accept a false equality by erasing literal kind. Only aggregate metadata is emitted.

Three nonempty groups belong to preservation-only databases/resultstable/version and are excluded from operational sharing. The proposed 55 operational names form 58 whole-table groups: 4,575 scoped payload occurrences would become 1,145 canonical typed rows, with 3,430 duplicate payload occurrences removed. Original preservation evidence stays intact. Category (6), subcategory (17) and task definitions (39) match across all five cities; task assignments and completion tables differ and remain scoped.

The coordinator independently combined the base approved schema with the proposed new tables, alias alterations and origin index, then checked case-insensitive column uniqueness, identifier lengths, parent exact unique keys, child FK index prefixes, referenced columns, RESTRICT actions and nonempty multi-city dependency-closed groups. All checks pass: 55 typed catalog definitions, 58 groups and 289 FKs in the affected combined definitions inspected. The generator also validates the enumerated counts and source memberships. New generator outputs use explicit LF line endings; the base schema hash remains the approved runtime SHA.

The design retains existing scoped operational IDs and same-city relationships as aliases, while storing one typed canonical payload. Alias membership and origin composite FKs bind city/source/table/snapshot/group. Payload-null CHECKs avoid retaining duplicate operational values once sharing is enabled. Whole-table equality and atomic publication remain cross-row service/reconciliation requirements; no CHECK is misrepresented as enforcing complete-table equality. Importers, reconcilers and readers need the canonical projection before conversion can activate.

Canonical payloads and published memberships remain read-only; new global catalog administration is not authorized. Source permissions are checked before following an alias, and a shared row ID grants no city access. Empty tables do not establish future shared write scope. Optional application-only parent links and actual restored typed values must still be independently validated before group publication. Hash equality alone does not authorize a changed snapshot, unresolved business semantics or a partial-table merge.

The proposal adds 57 tables, alters 55 aliases and adds one origin index. Those definitions were not part of the earlier approved P3.0 physical schema and still require explicit confirmation under the database architecture skill before migration code. No sharing DDL or conversion is implemented, and no private source rows are included in the repository.
